# 从本机实战提炼的经验

| 问题 | 复用方法 | 检查证据 |
|---|---|---|
| 解压目录一移动技能失效 | 安装到稳定 bundle，部署时写 local-engine.json | Python与CLI路径存在，cases可执行 |
| 装好技能却找不到工具 | 分开检查技能发现与MCP注册，重启客户端会话 | 安装回执、MCP工具列表、客户端实际调用 |
| CAD有多个图纸/进程 | 明确目标；自动落图创建自己拥有的新文档 | 文档标识、实体回读、保存路径 |
| 同一请求重复产生对象 | 写入后回读；超时先核实状态，再决定重试 | 实体数/操作记录 |
| DXF成功但DWG失败 | 输出状态分开，保留部分成功 | DXF解析与CAD保存回执各自检查 |
| 单位标签正确但尺寸错误 | 实际测量已知距离，核对单位缩放 | 原始量距、宽度和长度复算 |
| 路网改了而指标串地块 | 保留几何指纹绑定，逐块核对 | 面积、边界、attribute_geometry_bindings |
| 演示参数被当作规范 | synthetic/teaching标签随参数交付 | 参数来源、规范版本、未核验条件 |

已保存的 AutoCAD 2025 本机验收：原生实体共87（道路34、断面39、地块14），保存重读87，撤销/重做87→0→87。这是指定版本、指定合成测试的历史证据，不等于所有命令和所有电脑均通过。手动选择几何命令尚无完整覆盖；最终响应式面板修改尚无逐像素复查。完整范围以发行说明为准。

新用户复现顺序：安装回执 → CLI案例与校核 → MCP协议 → AI客户端实际调用 → 自有空白CAD新图落图 → 保存重开。任一项失败只影响对应层，不能用上一层成功替代下一层证据。
