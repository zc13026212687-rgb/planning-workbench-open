# 清规AI 控规实战流程

## 找到可执行入口

本技能由清规AI Starter 部署。先读取本技能目录的 `local-engine.json`；其中 `root` 是引擎目录，`python` 是已安装解释器。调用时使用这两个实际绝对路径，保留路径中的空格；不把文档中的变量名当成实际路径。

```powershell
$meta = Get-Content -Raw -Encoding UTF8 -LiteralPath '本技能实际目录/local-engine.json' | ConvertFrom-Json
& $meta.python -B '本技能实际目录/scripts/run.py' cases
& $meta.python -B '本技能实际目录/scripts/run.py' validate --spec '参数的绝对路径.json'
& $meta.python -B '本技能实际目录/scripts/run.py' generate --spec '参数的绝对路径.json' --out '尚不存在的成果目录'
```

如果配置文件不存在或引擎路径失效，说明技能尚未完整部署；使用 Starter 的部署/诊断入口，不凭空猜测 Python 路径。执行 CLI 的返回码和质量报告决定结果；成功安装不代表模型客户端已发现工具或 CAD 已绘图。

已注册 MCP 时可用 `planning_cases`、`planning_validate`、`planning_export`、`planning_export_control_sheet`。CLI 和 MCP 调用同一确定性引擎。MCP 不是读取当前 CAD 选择集的接口；当前选择集由 CAD 内 `QGROAD`/`QGPARCEL` 交互命令处理。

## 从任务到可编辑成果

1. **任务与证据。** 记录场地、原图、坐标/单位、边界、保留要素、外部道路接点、出图要求。沿用会话中已经明确的值，先检查文件可得信息，只询问影响正确性的缺项。北京大钟寺图片只能定位研究范围，未经定标不得当作测绘底图；本包例子是合成场地。
2. **确定协作方式。** 按用户意图选方式：A 由 AI 在已知约束内提出可计算的候选中心线；B 由 AI 给出 A/B/C 草案，用户选定后细化；C 用户在 CAD 绘制/选择中心线，由插件生成边界。A 是方案辅助，不是已实现无人监督的城市路网优化。一级/二级/三级为课程分级，必须另写道路宽度、接点和保留条件，不能自动等同法定等级。
3. **输入与预检。** 调用 cases 或读引擎 examples，按任务 schema 填 JSON。使用四个专业技能；道路、断面、地块分别校核。真实场地优先读取原始CAD/GIS几何；任意对象的自动提取未实现时明确用已有连接器或用户选择，不声称本技能能自动读完DWG。
4. **道路平面。** 中心线和左右方向固定后检查宽度、相切、短路段、连接及保留冲突。道路算法的 T/X 口 30–90°范围是当前计算支持范围。复杂 Y 口、复合直曲线、立交和不支持的折线应拆解或人工设计，不绕过校核。
5. **断面。** 为选定道路明确组件顺序、宽度、横坡和高程基准；平面总宽与断面宽度和必须一致或说明差异。负横坡表示向外下降。当前生成路表横断面，不虚构纵断面、排水和土方。
6. **地块与图则。** 核对闭合边界、孔洞、道路计算走廊、面积平衡与指标来源。未知指标保持空值。改路导致几何变化后重新核对指标归属，不根据P001编号自动继承。图则比例与源坐标用途分开。
7. **进入CAD。** 已安装原生插件时，在CAD中 `QGOPEN` 打开面板，`QGSPEC` 选择已校核JSON生成新图；`QGROAD` / `QGPARCEL` 走当前图纸人工选择流程。CLI/MCP 的 cad_new 使用另一条COM新图通道，不读当前选择集。沿用用户已授予的写图授权，未授权的写图先完成可审阅参数和DXF。
8. **验收与交付。** 读取质量报告、DXF单位/实体、CAD目标文档及保存回执。用户图纸中避免盲目重试：超时先回读是否已写入。撤销/重做测试放在本技能新建的测试图；不对用户工作图盲发UNDO。报告已完成文件、仍缺参数、未验证宿主环节和下一步。

最短合成练习见 [练习与提示词](references/quickstart.md)。排错和验收经验见 [实战经验](references/lessons.md)。需要当前规范时打开权威来源核对，不将引擎几何校核称为法定合规结论。
