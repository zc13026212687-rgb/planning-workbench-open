# 可选设计工具：从历史实战提炼的接入经验

控规道路、断面和地块教学的首发路线是 **清规AI 技能 → 原创计算引擎 → AutoCAD 或 DXF**。本页列出的软件用于可选的三维表达、GIS 数据准备或地图输出，不是 Starter 0.3.1 的必装依赖，也不会由入门包自动安装。

这里提供原创操作经验及官方、上游链接，不直接复制本机下载的第三方技能、宿主安装包、插件或材质。历史证据来自特定版本和工作站；换电脑、升级软件或切换客户端后，需要重新运行小型探针。

## SketchUp：验证整条桥接链路

历史路线是：**AI 客户端 → stdio MCP 服务 → 本机 TCP 服务 → SketchUp 内 Ruby 扩展 → 当前模型**。本机曾采用 [mhyrr/sketchup-mcp](https://github.com/mhyrr/sketchup-mcp) 作为桥接来源。其上游 README 与包元数据声明 MIT，但本次盘点的本地副本缺少完整 LICENSE 文件，作者元数据仍有占位项，并有本机修订；首发包因此只提供来源和接入经验，不附带该副本。

新机器按以下顺序检查：

1. 安装并正常启动使用者自己的 SketchUp，确认版本。依照选定桥项目的说明安装 Ruby 扩展，记录上游版本或提交与本地修改。
2. 在宿主内启动桥服务，确认它只监听预期的本机地址。历史使用端口为 `127.0.0.1:9876`，新配置以实际桥为准。
3. 在 AI 客户端配置该桥的 MCP 进程。先验证初始化和工具发现，再执行只读版本查询、当前模型查询及连续第二次调用。
4. 在独立测试模型内生成简单形体，保存为新文件，重新读取并检查实体与单位；需要视觉结果时导出图片检查。
5. 只有基础链路稳定后，才加入道路、地块和体量模型的交换流程。

曾遇到的具体问题是 Python 侧在发送命令前使用 Ruby 侧不支持的探针，且复用与服务端生命周期不符的连接，导致后续响应错位。修复遵循该版本服务端“一请求一连接”的协议，并通过连续调用复测。这是该桥特定版本的经验，不应推广成所有 MCP/TCP 桥都必须每条命令重连。

历史上读取到多个扩展已加载，只能证明扩展存在和加载状态。成功调用某个扩展的名称、版本接口，也不能证明该扩展所有建模、渲染功能已可自动操作。

SketchUp Ruby API 在宿主内运行，模型 API 调用应在主线程执行；长任务需要拆分，避免阻塞界面。具体接口以 [SketchUp 官方 Ruby API](https://ruby.sketchup.com/) 为准。

## 3ds Max：批处理与当前 GUI 场景分开验收

历史批处理探针在独立场景执行，写出版本 `2026 / 28.0.0.4098`、对象数 `0` 和空场景文件名。这证明指定脚本进入了真实批处理宿主，不代表它控制了已经打开的 GUI 场景。

推荐经验流程：

1. 从使用者的安装位置定位 `3dsmaxbatch.exe`，调用其帮助确认该版本参数；不要在技能中写入他人的固定盘符。
2. 先运行只读取版本和场景对象数的自有探针，同时检查退出状态、日志和预期结果文件。只有版本横幅不算脚本成功。
3. 处理已有模型时，显式选择输入文件；输出到新路径。对照单位、轴向、坐标平移、材质路径和渲染器依赖。
4. 导出或渲染后检查几何数量、缺失贴图、相机、输出尺寸和实际图片。批量渲染成功不等于规划设计通过专业校核。

既有项目曾形成可编辑场景、分类渲染与多图总览，并审计了对象、材质和缺失贴图；这些是历史案例成果，不属于本仓库的可分发示例。尤其不能把随商业软件安装的材质库直接打包成项目素材。

启动选项、MAXScript 和 Python 接口请查使用版本的 [Autodesk 3ds Max 官方帮助](https://help.autodesk.com/view/3DSMAX/2026/ENU/)。

## QGIS：探针成功后，还要检查地图像素

历史探针记录了可用原生 provider、有效合成图层、1 个要素、坐标声明、原生 buffer 算法可用，以及 PDF 导出返回 0。导出成功后仍出现过字体方块；显式注册已安装字体并设置布局文本后，PNG/PDF 才得到正确显示。因此“返回码正常”和“地图可读”需要分别检查。

新环境应使用安装发行版提供的 PyQGIS 启动环境，不能把普通系统 Python 当作已经具备 QGIS。先用一个合成要素完成初始化、图层读取、原生算法和布局导出，再处理真实资料；结束时释放应用资源。独立 Python 进程通常操作项目文件，不代表正在编辑用户打开的 GUI 项目。接口和示例见 [PyQGIS 官方开发手册](https://docs.qgis.org/latest/en/docs/pyqgis_developer_cookbook/)，并切换到与安装版本匹配的文档。

进入 CAD 前必须确认数据源 CRS、单位、范围和几何有效性。缺少 CRS 时保留缺项，向数据来源核对；不能只凭坐标数值猜一个 CRS。面积与距离计算选择适合场地的投影，并记录转换与坐标平移。CAD 图上“米”单位不等于已经拥有可追溯的地理坐标系。

## ArcGIS Pro：ArcPy 成功不等于第三方 CLI/MCP 成功

ArcPy 是 ArcGIS 的 Python 接口，可用于地理分析、数据管理和地图自动化，见 [Esri 官方 ArcPy 说明](https://doc.esri.com/en/arcgis-pro/latest/arcpy/get-started/what-is-arcpy-.html)。本机历史探针通过了安装信息、授权状态、项目、地图、图层和布局读取；同时识别到一个项目存在失效数据源。不能因为 ArcPy 能启动，就忽略项目内的断链图层。

本地曾保存名为 `cli-anything-arcgis-pro` 的技能说明，但本次盘点没有找到可直接解析的同名 CLI 命令，也未核实其源码上游和完整许可。现有 ArcPy 成果**不证明**该 CLI 的全部命令或 live MCP 桥已经安装、连通和验证。因此本包不包含该第三方技能，也不把它列为一键部署成功项。

可复用的最小路线为：

1. 使用 ArcGIS Pro 配套或已正确配置的 ArcPy 环境，读取安装版本和当前可用授权，不绕过授权条件。
2. 明确输入项目，枚举地图、布局和失效数据源；仅在资源可用的范围内继续。
3. 使用复制项目或独立输出目录完成一次小型处理/布局导出，核对结果文件和图像。
4. 若需要操作当前打开的 Pro 窗口，另行确认在宿主内运行的 add-in/MCP 桥、工具列表和实际调用证据。命令行读取一个项目文件，与控制当前 GUI 会话是不同能力。

## 把经验写成可迁移技能

每个后续扩展技能只需要先解决六件事：宿主与版本探测、使用者自己的路径配置、最小只读探针、合成数据操作、可编辑成果回读、明确的失败原因和能力范围。历史日志用于设计探针，新机器的成功结论必须来自新机器自己的结果。

与清规AI交换成果时，随几何保存单位、CRS/本地坐标说明、原点或平移量、图层语义、输入参数、版本与来源。三维表达软件生成的漂亮画面，不能替代道路拓扑、地块面积与控制指标校核。技能、桥、宿主和案例数据各自记录来源与许可，避免把“本地可用”误写成“全部可以公开再分发”。
