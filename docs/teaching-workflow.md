# 控规课程：从AI提案到可编辑CAD成果

目标是把设计判断、结构化参数、几何计算和实际出图区分清楚，让学生可以解释每条道路如何产生、哪些参数来自任务书、哪些仍是方案假设。

## 六个教学阶段

| 阶段 | 学生或教师的输入 | 技能/工具 | 可检查的输出 |
|---|---|---|---|
| 资料与定标 | DWG/GIS、任务书、研究边界、已知长度、保留条件 | beijing-regulatory-cad | 单位/坐标/来源表和缺项 |
| 路网草案 | 外部接点、课程道路分级、宽度、保留要素 | qinggui-cad-workflow + road-plan | 中心线候选、冲突与方案差异 |
| 道路细化 | 选定中心线、左右宽度、路口参数 | planning-cad-road-plan / QGROAD | 边线、真圆弧、连接与错误报告 |
| 横断面 | 组件顺序、宽度、横坡、基准高程 | planning-cad-cross-section / QGSECTION | 路表线、高程计算、宽度和 |
| 地块与图则 | 闭合边界、孔洞、道路走廊、明确控制指标 | planning-cad-regulatory-suite | 地块、指标表、面积平衡、单地块图则 |
| 成果验收 | 原图与新成果的对照要求 | 原生插件 / CLI / CAD回读 | DXF、实际保存的DWG、参数、QA与未解决条件 |

## 三种协作方式

**A：AI提出方案。** 在已经明确的边界、接点和约束内，AI组织候选中心线与参数，调用计算引擎检查。当前版本不包含自动交通分配或全局路网优化器，不能将草案质量等同专业论证完成。

**B：AI给出可比较选项，学生选择。** 让A/B/C方案使用相同底图、单位与保留条件，比较道路总长、冲突、接入关系及地块变化。选择后再细化。建议作为本科课堂主流程，保留学生的设计理由。

**C：学生画中心线，AI辅助细化。** 在CAD中用真实底图定位，以 `QGROAD` 选择受支持的中心线，输入宽度后生成边界。复杂路口继续人工设计；超出算法范围应明确显示错误。

三个方式描述人机分工，不意味着本包已经实现自动识别卫星图并直接编制全套控规。

## 北京大钟寺如何进入流程

公开包不含课程DWG、私人PPT或卫星图复制件。使用者提供自己有权使用的底图后，先核实边界和定标，再把道路草案写成参数。课程中的“一级、二级、三级”先作为分级方案标签，分别记录宽度与功能；需要引用法定道路等级时另核查规划依据。没有实测或获批资料时，教学设计仍标为方案假设。

道路宽度变化后检查断面总宽；道路/边界变化后检查地块指标的几何绑定；图则中的缩放示意不能回作原坐标地形数据。保留原始文件，每轮使用新成果目录，记录版本及修改理由。

## 可以用于课堂的验收问题

1. 我们如何知道图上1个单位对应什么长度？
2. 中心线方向改变后，左右宽度的含义是否改变？
3. 路口圆弧是否真正相切，还是视觉上接近？
4. 横断面宽度和与道路平面总宽是否一致？
5. 道路切分后，场地面积、道路占地、孔洞和地块面积是否守恒？
6. P001几何变化后，原有指标是否仍属于这个地块？
7. 成功导出DXF、成功在CAD生成、成功保存并重开DWG，分别有什么证据？

图形自动化可以减轻重复计算与绘制，设计合理性仍需要场地调研、规范依据、交通与空间判断。课程可以围绕这些具体问题评价学生，而不是只评价演示速度或图面数量。
